# Nishant Chaudhary

Nishant leads the Build lane at Digitribe. He has spent five-plus years shipping production frontend systems at scale — the kind where a broken deploy affects hundreds of thousands of users and a poorly structured component library costs teams months of velocity.

Before Digitribe, he built micro-frontend platforms, internal design systems, and AI-native developer tooling inside organizations where engineering standards were non-negotiable. He's the kind of engineer who reads Lighthouse output for fun, writes zero-any TypeScript by default, and considers a slow LCP a personal failure.

His stack is deep in React, Next.js, and TypeScript, but he's shipped in Vue, Shopify Liquid, and Webflow too. He built Nishant's Turborepo — a 14-app, 8-package monorepo housing everything from MCP tooling to 3D portfolio experiments — as a personal engineering lab. He's comfortable owning the full frontend SDLC: architecture, build, CI/CD, performance, and handoff.

## What he believes about the work

Good frontend is invisible. Users don't notice when a site loads in 0.8 seconds, doesn't shift layout, and never shows a broken state. They notice when it doesn't. Nishant optimizes for the invisible — performance budgets, accessibility baselines, semantic HTML, and resilient state management — so that what you launch actually works at scale.

He also believes that agencies have broken client trust by assigning senior talent to sales and junior talent to delivery. At Digitribe, he does both. If he sold you, he's also building it.

## Philosophy

- Code that ships is better than code that's perfect, but perfect code ships more reliably over time.
- The most important performance metric is the one the user experiences, not the one in the CI report.
- A clean handoff with documentation is a deliverable. Dumping a git repo is not.
